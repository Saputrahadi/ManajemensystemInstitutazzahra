# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

**Az-Zahra Digital Campus**, a Laravel-based campus/SIAKAD system for Institut Az-Zahra, per the project's Master Blueprint. **Fase 0 (Core System)** is complete: **Login → User → Role → Permission → Unit/Organisasi → Audit Log → Notifikasi → Dokumen → Settings** — all nine implemented (see Architecture below).

**Fase 1, Prioritas 1 (PMB) is functionally complete end-to-end** — public registration through NIM issuance, verified via tinker and real Filament UI clicks. `App\Models\Pmb\*` (12 migrations matching the blueprint's PMB ERD tables exactly, `admission_periods` through `re_registrations`, plus `nim_counters` — not in the blueprint ERD, a row-locked sequence counter for NIM generation). Public `GET /pmb/daftar` registration form (Livewire, no login). Filament resources (nav group "PMB") for periods/paths/tests/applicants, permission-gated. Full seleksi workflow as `App\Services\Pmb\*` services invoked from Filament Actions/RelationManagers on `ApplicantResource`: document verification, test/interview results, score computation, admission decision, re-registration → NIM. See [docs/pmb.md](docs/pmb.md).

**Fase 1, Prioritas 2 (SIAKAD) is in progress, built domain-by-domain.** Sub-domain **Mahasiswa** is done: `App\Models\Mahasiswa\*` (`students` + `student_profiles`/`addresses`/`families`/`documents`/`status_histories`, fields matching the blueprint's own `students` ERD entity exactly). `App\Services\Mahasiswa\StudentEnrollmentService` converts a completed PMB `ReRegistration` into a `Student` + `User` account (role `mahasiswa`) automatically — wired as a Filament Action on `ApplicantResource`, verified end-to-end via tinker and real UI clicks. `StudentResource` (nav group "Mahasiswa"), permission-gated. See [docs/mahasiswa.md](docs/mahasiswa.md). Sub-domain **Dosen** is done: `App\Models\Dosen\*` (`lecturers` + `lecturer_profiles`/`educations`/`expertises`/`assignments`) — no application flow like PMB, `LecturerResource`'s custom Create/Edit pages create/update `User` (login, role `dosen`) + `Lecturer` together in one transaction, mirroring `EmployeeController` from `sistem-yayasan-laravel`. See [docs/dosen.md](docs/dosen.md). Sub-domain **Kurikulum** is done: `App\Models\Kurikulum\*` (`curricula`, `courses`, `curriculum_courses` pivot with `semester`/`is_mandatory`, self-referencing `course_prerequisites`, `learning_outcomes` (CPL), `course_learning_outcomes` (CPMK)) — `students.curriculum_id`'s FK (left unconstrained when the Mahasiswa domain was built) is now added via `2026_08_21_500160_add_curriculum_foreign_to_students_table`. `CurriculumResource`/`CourseResource`/`LearningOutcomeResource` (nav group "Kurikulum"), permission-gated, verified via tinker and real UI clicks including the pivot-form `AttachAction` and self-referencing relation manager. See [docs/kurikulum.md](docs/kurikulum.md). **Fase 1, Prioritas 4 (Sistem Dosen) is done** — unlike Prioritas 1-3, this isn't a new Filament admin module: it's a **lecturer self-service portal** (`routes/dosen.php`, pure Livewire, layout `components.layouts.app`) sitting on top of data structures the SIAKAD sub-domains already built (Kelas, Presensi, Materi, Tugas, Nilai). Gated by the `lecturer` middleware alias (`App\Http\Middleware\EnsureUserIsLecturer` — role `dosen` **and** a `Lecturer` row must exist, distinct from the `admin`/`permission:` middleware that gates `/admin`), plus a second per-page authorization check in each Livewire component's `mount()` (e.g. `Kelas\Show` verifies the logged-in lecturer actually teaches that class — confirmed for real: hitting `/dosen/kelas/{id}` for a class taught by a different lecturer returns a genuine `403 Anda bukan pengampu kelas ini.`, not just a hidden button). `Kelas\Show` is the core page — one Livewire component, four tabs (Presensi/Materi/Tugas/Nilai), mirroring the "relation-manager-as-tab" pattern used throughout the Filament resources this session but built in plain Livewire; its Nilai tab's "Finalisasi" button calls the exact same `GradeFinalization::computeWeightedScore()`/`scoreToScale()` used by `GradeFinalizationResource`'s "Hitung Ulang" action in Filament — one calculation, two entry points. Two genuinely new pieces of schema: `students.advisor_id` (Dosen Wali, assigned by admin via `StudentResource`) and `academic_advisings` (Bimbingan Akademik, `App\Models\Dosen\AcademicAdvising`). Verified by actually logging in as a seeded lecturer account (not superadmin) and clicking every tab: creating a class session, marking attendance, adding a grade component, entering a score, finalizing a grade (88% weight × 88 score → `88.00`, confirmed on screen), creating an assignment, uploading course material (via Livewire's built-in `WithFileUploads`, same disk/directory as the existing Filament `MaterialsRelationManager`), and recording an advising session. See [docs/sistem-dosen.md](docs/sistem-dosen.md).

Later phases (PDDIKTI/EMIS integrations, Administrasi Internal — SDM/Aset/Persuratan/Perpustakaan/etc., a student self-service portal) are not implemented — `.env.example` reserves config slots for PDDIKTI/EMIS so `.env` won't need restructuring later.

Unlike the `sistem-yayasan-laravel` package, this **is** a complete, standalone Laravel 11 app (`composer.json`, `artisan`, `bootstrap/`, `config/` all present). It has since been run end-to-end (composer/npm install, migrate, seed, served, and exercised through the browser) — see **Known setup gotchas** below for issues that surfaced only by actually running it.

## Commands

```bash
composer install
cp .env.example .env
php artisan key:generate

# DB is PostgreSQL (DB_CONNECTION=pgsql in .env.example); create it first
createdb az_zahra_digital_campus

php artisan migrate --seed   # or migrate + db:seed separately
npm install
npm run dev     # or `npm run build` for production assets

php artisan serve
```

Run tests (uses in-memory SQLite regardless of the app's configured DB — see `phpunit.xml`):

```bash
php artisan test
php artisan test --filter=RbacUnitScopingTest   # single test class
```

Tests are organized per module under `tests/Feature/<Module>/` (currently only `Core/`, since Fase 0 is the only module) — put new domain tests in a matching subfolder rather than flat in `tests/Feature/`, following the structure in the Master Blueprint.

`scripts/` holds ops scripts (`deploy.sh`, `backup.sh`, `maintenance.sh`) for a Linux target — see [docs/sop/deployment.md](docs/sop/deployment.md). `docs/` holds human-facing architecture docs and SOPs (Indonesian, matching the rest of the project) — start at [docs/README.md](docs/README.md); this CLAUDE.md file is the AI-agent-facing counterpart and intentionally overlaps with [docs/architecture.md](docs/architecture.md) rather than deferring to it.

Seeding creates one Super Admin: email `superadmin@az-zahra.ac.id`, password from `SEED_SUPERADMIN_PASSWORD` in `.env` (set this before seeding — fallback is `ganti-password-ini`, never use it in production). Regular login is at `/login`; the Filament admin/CRUD panel is at `/admin`.

CI (`.github/workflows/tests.yml`) runs against PHP 8.3/8.4/8.5 with a fresh `.env` copy and no seeding — just `composer install`, `key:generate`, `php artisan test`.

## Architecture

**Namespace convention**: per blueprint `#folder`, Fase-0/Core code lives under a `Core` sub-namespace in five places — `App\Models\Core\*`, `App\Http\Controllers\Core\*`, `App\Services\Core\*`, `resources/views/core/`, `routes/core.php` + `routes/core-api.php` (the top-level `routes/web.php`/`routes/api.php` are just thin `require` loaders). **Exception: `App\Models\User` deliberately stays un-namespaced** — it's the Authenticatable anchor referenced directly by `config/auth.php`, Sanctum, and a hardcoded fallback in Filament's Import/Export actions; moving it would ripple through the whole ecosystem for no real benefit. `app/Policies/`, `app/Livewire/`, `app/Filament/Resources/`, and `app/Notifications/` are **not** namespaced per-module — the blueprint's five-location convention doesn't name them, and Livewire/Filament auto-discovery makes moving them fragile for no benefit.

**Database table names match the blueprint's ERD exactly**, not idiomatic Laravel defaults: `organizational_units` (not `units`), `user_roles` (not `role_user`), `role_permissions` (not `permission_role`). The `Unit` *model class* still exists (too deeply embedded in RBAC to rename) but points `protected $table = 'organizational_units'`.

**RBAC + data-scoping is the core of this phase.** Everything else exists to support it:
- `User` ↔ `Role` is many-to-many via `user_roles`, and the pivot itself carries a `unit_id` ([app/Models/User.php](app/Models/User.php)). A role assignment with `unit_id = null` means the role is **institution-wide** (`hasInstitutionWideRole()`); a non-null `unit_id` scopes that role assignment to one unit.
- `Role` ↔ `Permission` is many-to-many via `role_permissions`. `User::hasPermission()` checks across all of a user's roles.
- `Unit` ([app/Models/Core/Unit.php](app/Models/Core/Unit.php)) is a self-referencing tree (`parent_id`/`children()`/`descendants()`) with a free-text `type` column (institut, fakultas, prodi, biro, ukm, ...) — new org unit types are added via data, not migrations. Institut/Fakultas/Prodi rows stay in this same tree (so RBAC scoping is untouched) but each also has a **companion table** — `Institution`/`Faculty`/`StudyProgram` (`App\Models\Core\*`), linked 1:1 via `organizational_unit_id` — holding blueprint-ERD-specific fields (`dean_user_id`, `accreditation`, `degree_level`, etc.) that don't belong on a generic org-unit row. Access via `Unit::institution()`/`faculty()`/`studyProgram()`.
- The `HasUnitScope` trait ([app/Models/Core/Concerns/HasUnitScope.php](app/Models/Core/Concerns/HasUnitScope.php)) provides `Model::query()->visibleTo($user)`: institution-wide roles see everything; otherwise the query is restricted to the union of the user's `scopedUnitIds()` **plus all descendant units** (e.g. a Dean scoped to a Faculty automatically sees every Prodi under it). Attach this trait to any model with a `unit_id` column (or override `unitScopeColumn()`) that needs per-unit visibility.
- Route-level enforcement uses the `permission:<code>` middleware alias ([app/Http/Middleware/EnsureUserHasPermission.php](app/Http/Middleware/EnsureUserHasPermission.php), registered in [bootstrap/app.php](bootstrap/app.php)) — default-deny, requires an exact permission code.
- Row-level enforcement uses Policies (e.g. [app/Policies/UserPolicy.php](app/Policies/UserPolicy.php)), which combine a permission check with `sameOrDescendantUnit()` — same descendant-unit logic as `HasUnitScope`, but for a single target record rather than a query.
- The canonical test scenario for all of this is "Kaprodi Prodi A tidak bisa lihat data Prodi B" — see [tests/Feature/Core/RbacUnitScopingTest.php](tests/Feature/Core/RbacUnitScopingTest.php), which also covers institution-wide roles and descendant-unit visibility (Dean → child Prodi). Any change to `HasUnitScope`, `scopedUnitIds()`, or `hasInstitutionWideRole()` should keep these passing — notably, splitting out Institution/Faculty/StudyProgram required **zero** changes to this test file, confirming the companion-table design didn't disturb RBAC.

**Audit trail is automatic, not manual.** The `Auditable` trait ([app/Models/Core/Concerns/Auditable.php](app/Models/Core/Concerns/Auditable.php)) hooks `created`/`updated`/`deleted` model events and writes to `AuditLog` with before/after diffs, actor, IP, and user agent — attach it to any model and it just works, with no controller/service code needed. A model opts sensitive or noisy columns out of the diff via a `protected array $auditExcept = [...]` property (see `User::$auditExcept` excluding `password`, `remember_token`, `last_login_at`, `last_login_ip`). `updated` events with only excluded-column changes (e.g. `updated_at`) don't write a log row at all.

**Two separate auth surfaces:**
- `App\Livewire\Auth\Login` ([app/Livewire/Auth/Login.php](app/Livewire/Auth/Login.php)) is the Core System login for non-admin users at `/login`. It accepts email-or-username, rate-limits by `login|ip` (5 attempts / 60s lockout), checks `status === 'aktif'`, and writes both `last_login_at/ip` and an `AuditLog` row on success. It now actually leads somewhere for lecturers: the generic `core.dashboard` view links to `/dosen` (the Sistem Dosen portal, see Prioritas 4 above) when `$user->hasRole('dosen') && $user->lecturer`. A Mahasiswa-facing counterpart doesn't exist yet.
- The Filament panel at `/admin` ([app/Providers/Filament/AdminPanelProvider.php](app/Providers/Filament/AdminPanelProvider.php)) has its own independent `->login()` and is where CRUD for User/Role/Permission/Unit/Document/Setting and the read-only Audit Log viewer live ([app/Filament/Resources/](app/Filament/Resources/)). Per the blueprint, Filament is deliberately scoped to "modules that are pure CRUD" rather than the whole system — don't assume every future module gets a Filament resource. `DocumentResource` and `SettingResource` are gated by `DocumentPolicy`/`SettingPolicy` (both single-permission: `core.document.manage`/`core.setting.manage`) — note `UnitResource`/`RoleResource`/`PermissionResource` have **no** policy class, so Filament currently lets any authenticated panel user manage them; only `User`, `AuditLog`, `Document`, and `Setting` are actually permission-gated. `Institution`/`Faculty`/`StudyProgram` have no Filament resource at all yet (model+migration+seeder only).
- In-app notifications use Laravel's standard `database` notification channel (`User` already has `Notifiable`). `App\Notifications\GenericNotification` ([app/Notifications/GenericNotification.php](app/Notifications/GenericNotification.php)) is a generic title/body/url notification any future module can fire via `$user->notify(new GenericNotification(...))` without writing a new Notification class. The bell dropdown is a Livewire component, `<livewire:notification-bell />` ([app/Livewire/NotificationBell.php](app/Livewire/NotificationBell.php)), mounted in the shared layout nav — it is the only piece of interactive Fase-0 UI outside Filament and the login page.
- `SettingResource`'s create/edit pages manually clear the `setting:{key}` cache key (`Setting::get()` caches for 1h) since editing through Filament's Eloquent save doesn't go through `Setting::set()`.

**API** ([routes/core-api.php](routes/core-api.php), loaded via [routes/api.php](routes/api.php)) is versioned under `/v1`, Sanctum-authenticated, and follows a fixed response envelope (`{success, data, meta}` / `{success, message, errors}`) per the blueprint's `#api` convention. `/api/v1/me`, `/api/v1/units`, `/api/v1/audit-logs` are served by `App\Http\Controllers\Core\Api\*`; each new domain gets its own `routes/<domain>-api.php` required from `routes/api.php`, rather than growing `core-api.php` — [routes/keuangan-api.php](routes/keuangan-api.php) is the second example, and it deliberately breaks the `/v1` + Sanctum convention for its one route: `POST /api/bsi/callback` is an inbound webhook from an external bank, not an internal client, so it's authenticated by a static token header instead (see `App\Http\Middleware\VerifyBsiCallbackToken`, aliased as `bsi.callback` in `bootstrap/app.php`).

**Seeding order is dependency-driven** ([database/seeders/DatabaseSeeder.php](database/seeders/DatabaseSeeder.php)): `Unit → Permission → Role → SuperAdmin` — Units must exist before Role scoping, Permissions before `Role::permissions()->sync()`, and Super Admin last since it needs both. [UnitSeeder](database/seeders/UnitSeeder.php) also creates the companion `Institution`/`Faculty`/`StudyProgram` rows alongside each institut/fakultas/prodi `Unit`. [RoleSeeder](database/seeders/RoleSeeder.php) seeds 12 core roles (abbreviated from 29 full user types in the blueprint — notably still missing the blueprint's later split of "Dosen" into Dosen Pengampu/Dosen Wali and "Operator" into Operator PMB/Operator Sarpras); role-specific derivatives (e.g. Admin PMB, Admin Keuangan) are meant to be added later through the Filament `RoleResource` rather than new seeder code.

## Known setup gotchas

Discovered by actually running the app for the first time — none of these are visible from reading the code alone:

- **`composer.json`'s `laravel/pao` (require-dev) is incompatible** with `laravel/framework ^11.0` (it requires Laravel ^12) — was removed from `require-dev`. If re-adding dev tooling, verify against the pinned `^11.0` framework constraint first.
- **`config/database.php` used `Pdo\Mysql::ATTR_SSL_CA`**, a PHP 8.4-only native class, evaluated eagerly inside the `mysql`/`mariadb` connection arrays — this crashes on any PHP < 8.4 as soon as the config file is loaded, even if you never connect to MySQL. Fixed to use the older, equivalent `\PDO::MYSQL_ATTR_SSL_CA` constant.
- **The `documents` migration double-declared an index**: `nullableMorphs('documentable')` already creates an index on `(documentable_type, documentable_id)`; an explicit `$table->index([...])` for the same columns right after it caused `migrate` to fail (at least on SQLite). Removed the redundant explicit index.
- **`composer.json` pins `optimize-autoloader: true`**, so the autoloader is classmap-based — adding a new PHP class file (e.g. a new Filament Resource/Page/Policy) is invisible to the app until `composer dump-autoload` runs, even though PSR-4 would normally pick it up automatically. Forget this step and you'll see `Class "..." not found` errors that look unrelated to what you just added.
- **`php artisan filament:assets` was never run**, so `public/css/filament/*` and `public/js/filament/*` 404'd — this silently broke *all* interactive panel chrome (sidebar collapse/expand, file upload widget, inline validation error rendering), not just newly-added resources. Re-run this after any `composer update` that touches a `filament/*` package.
- `.env.example` defaults to `pgsql`/`redis` for DB/session/cache/queue; for local dev without those services, `sqlite` + `file`/`sync` drivers work fine and match what `phpunit.xml` already uses for tests.
- **SQLite returns `decimal`-cast columns as raw PHP floats (not strings) once a model is re-queried**, which Laravel's `decimal:N` cast forwards straight into `Brick\Math\BigDecimal::of()` — a call that `brick/math` has deprecated for float input (will hard-error in 0.15). PostgreSQL/MySQL return decimal columns as strings, so this is SQLite-only and won't reproduce in production. Any code path that reads a `decimal`-cast attribute off a freshly-queried (not freshly-created) model for arithmetic must use `$model->getRawOriginal('column')` instead of the normal accessor — see `App\Models\HasilAkademik\StudentSemesterResult::computeForPeriod()` for the pattern and [docs/hasil-akademik.md](docs/hasil-akademik.md) for the full writeup (found via `set_error_handler()` + `debug_print_backtrace()` in tinker, not code review). Filament `TextColumn`s that merely *display* a decimal value still trigger the same deprecation notice on SQLite — left as-is since it's cosmetic (log noise only, no data ever computed from it).

## Conventions

- Code comments, UI strings, and blueprint references are in Indonesian; the blueprint itself is referred to inline as `#<section>` (e.g. `#keamanan`, `#arsitektur`, `#api`) — these are pointers into an external Master Blueprint document, not files in this repo.
- Style: `laravel` preset via StyleCI ([.styleci.yml](.styleci.yml)), `laravel/pint` available as a dev dependency.
